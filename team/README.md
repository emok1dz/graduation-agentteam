# Agent Team 组建与分工

由 Leader（组长）根据题目方向动态组建团队，按“需求 → 设计 → 开发 → 测试 → 论文 → 答辩”五阶段推进。
各角色只做本职工作、只写自己负责的目录；跨角色依赖通过**契约文件**传递（需求规格 → API 契约 → 代码 → 测试报告 → 论文/答辩）。

| 角色 | 职责 | 产出目录 | 输入依赖 |
| --- | --- | --- | --- |
| Leader（组长） | 拆解任务、组建团队、分阶段验收、整合交付 | `team/` | 题目 |
| 需求分析师 | 背景调研、用例图、功能/非功能需求、需求追踪矩阵 | `requirements/` | 题目 |
| 系统架构师 | 技术选型、架构图、ER 图、API 契约、数据模型 | `design/` | requirements/ |
| 后端开发者 | API 实现、数据模型、业务逻辑、鉴权 | `backend/` | design/ |
| 前端开发者 | 页面/组件、交互、状态管理 | `frontend/` | design/ |
| 测试工程师 | 单元/集成/E2E 测试、覆盖率、测试报告 | `backend/test/`、`docs/test-report.md` | backend/、frontend/、requirements/ |
| 论文撰写者 | 整合全阶段产出为 6 章论文 | `thesis/` | 全部 |
| 答辩助手 | PPT 大纲、演示脚本、预测 Q&A | `defense/` | 全部 |

## 题目与方向

- **题目**：在线考试系统
- **方向**：全栈 Web 系统
- **技术栈**：Node.js（原生 `node:http`，零第三方依赖）+ 原生 JavaScript 单页应用；数据持久化为 JSON 文件存储（可替换为 MySQL，DDL 见 design/database/ddl.sql）
- **系统角色**：管理员 / 教师 / 学生
- **核心功能**：用户与班级管理、题库管理、组卷与发布考试、在线答题（倒计时、自动交卷）、自动阅卷 + 主观题人工阅卷、成绩统计

阶段执行记录见 [team/log.md](log.md)。
